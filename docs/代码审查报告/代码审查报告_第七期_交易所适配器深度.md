## 一、三大交易所持仓同步均失效

### 🔴 1. 【严重】Binance 持仓同步为空列表 —— 策略无法感知已有持仓
文件: binance.py:175-176
```python
async def get_positions(self, symbol: str | None = None) -> list[PositionInfo]:
    return []  # ← 硬编码返回空列表
```
问题: Binance USDT-M Futures 账户的持仓数据完全无法获取。策略每次启动都会认为没有持仓，
可能导致重复开仓或无法平掉已有仓位。

### 🔴 2. 【严重】Huobi 持仓同步为空列表
文件: huobi.py:234-235
```python
async def get_positions(self, symbol: str | None = None) -> list[PositionInfo]:
    return []  # ← 硬编码返回空列表
```
问题: 同上，火币的永续/逐仓持仓无法同步。

### 🟠 3. 【中等】OKX 持仓方向 posSide="net" 未映射
文件: okx.py:240-243
```python
side=p.get("posSide", "net"),  # ← "net" 不是有效 side
```
问题: net 表示净持仓，long/short 可能都为 net。需要根据 quantity 正负判断实际方向。

## 二、OKX 条件单（止损止盈）tdMode 错误

### 🔴 3. 【严重】OKX 止损止盈单用 tdMode=cash —— 永续合约永远无法触发
文件: okx.py:351-357
```python
body_dict = {
    "instId": inst_id,
    "tdMode": "cash",  # ← 永续合约条件单也必须用 cross/isolated
    "side": side.lower(),
    "ordType": "conditional",
    "slTriggerPx": str(stop_price),
    "slOrdPx": "-1"
}
```
问题: 止损止盈条件单同样使用 tdMode=cash，永续合约的条件单会被 OKX 拒绝，
策略的风控止损/止盈功能完全失效。

## 三、订单数量精度问题

### 🟠 4. 【中等】Binance quantity 格式化和 minQty 校验缺失
文件: binance.py:192
```python
quantity: f"{quantity:.8f}".rstrip("0").rstrip("."),
```
问题: 1. 仅 rstrip 0/1 可能使数量位数超过 minQty 步进（如 minQty=0.001 时 0.0010 变成 0.001OK，
但 minQty=0.01 时 0.001 会被拒绝。
2. 没有调用 /exchangeInfo 获取 minQty，直接用 8 位小数格式化大概率被拒。

### 🟠 5. 【中等】OKX quantity 传入原始精度可能不符合步进要求
文件: okx.py:267
```python
"sz": str(quantity),  # ← 原始 Decimal 直接转字符串
```
问题: OKX 的 sz 字段必须符合 instId 对应的精确度步进（如 BTC-USDT-SWAP 是 0.0001），
如果不取整可能报 51001 错误。

### 🟡 6. 【轻微】Huobi 限价单未设置 price-precision
文件: huobi.py:253
```python
body = {
    ... "price": str(price),  # ← 原始精度直接用
}
```
问题: 火币限价单需要 price-precision 参数，如果不提供且精度不对会被拒。

## 四、Huobi 账户缓存竞态与重试问题

### 🟠 7. 【中等】Huobi _get_account_id 多实例竞态 —— 类变量缓存导致并发错误
文件: huobi.py:55-116
```python
self._account_id: str | None = None  # ← 实为实例变量，但逻辑有缺陷
async def _get_account_id(self) -> str:
    now = time.monotonic()
    if self._account_id and (now - self._account_id_fetched_at < self._ACCOUNT_ID_TTL):
        return self._account_id
```
问题: 1. _account_id_fetched_at 缓存 TTL=300秒，但在此期间如果账户余额变动，
缓存的 account_id 可能指向已删除/无效账户。
2. 如果 _invalidate_account_id_cache() 被调用后立即并发请求，多个协程可能同时触发重新获取。

### 🟠 8. 【中等】Huobi create_stop_order 用 v2 接口但 body 字段不匹配
文件: huobi.py:315-322
```python
body = {
    "accountId": account_id,   # ← v2接口可能用 account-id（小写）
    "orderType": "market",     # ← 字段名可能不匹配
    "type": otype,
    "stopPrice": str(stop_price),
}
params = self._sign_params("POST", "/v2/order/algo")  # ← 用 v2 签名
```
问题: Huobi 的 v2/order/algo 接口文档与 v1 不同，body 字段如 accountId vs account-id，
可能导致订单提交失败但无明确错误信息。

## 五、共享 HTTP 客户端资源泄漏

### 🟠 9. 【中等】BaseExchangeAdapter._shared_client 类变量共享 —— 多账户数据串台
文件: base.py:125-143
```python
class BaseExchangeAdapter(ABC):
    _shared_client: httpx.AsyncClient | None = None  # ← 类变量，所有子类共享
```
问题: 同一个适配器类（如 BinanceAdapter）的所有实例共用同一个 httpx.AsyncClient，
如果一个实例关闭了 client，其他实例也会受影响。
更严重的是：如果不同账户共用同一个 adapter（虽然一般不会），但共用 client 会导致
请求头中的 API Key 混淆。

### 🟡 10. 【轻微】HTTP Client 无超时重置机制
文件: base.py:142
```python
cls._shared_client = httpx.AsyncClient(timeout=30.0)  # ← 固定超时，永不重置
```
问题: client 创建后永不关闭，网络变化（如切换 VPN）后连接池可能已失效，
需要重新创建 client。

## 六、重试与限流问题

### 🟠 11. 【中等】_classify_error 对 401/403 全部映射为 OrderRejectedError
文件: base.py:157-165
```python
if status_code in (400, 401, 403):
    return OrderRejectedError(...)  # ← 401 本该是认证失败，不应重试
```
问题: 401 Unauthorized 应该立即退出并告警，而不是当作可重试的 OrderRejectedError。
当前重试逻辑会把 401 也重试 3 次，每次等待退避，浪费资源和时间。

### 🟡 12. 【轻微】OKX 时间同步 _time_offset_ms 可能在多实例间互相覆盖
文件: okx.py:47-48
```python
_time_offset_ms: int = 0   # ← 类级别变量！
_time_synced: bool = False  # ← 类级别变量！
```
问题: _time_offset_ms 和 _time_synced 是类变量（类级别共享），
如果创建多个 OKXAdapter 实例，它们的 offset 会互相覆盖，
导致某些实例用的偏移是其他实例同步的结果。

## 七、其他问题

### 🟡 13. 【轻微】Binance 订单簿 symbol 未大写
文件: binance.py:138
```python
params={"symbol": symbol, "limit": limit},  # ← 未 .upper()
```
Binance API 要求 symbol 必须大写（如 BTCUSDT），如果传入小写会返回 400。

### 🟡 14. 【轻微】Huobi ticker timestamp 字段映射错误
文件: huobi.py:154
```python
timestamp=datetime.fromtimestamp(float(_safe_decimal(tick.get("version")) / 1000), ...)
```
问题: tick.version 是行情版本号，不是时间戳。应该用 tick.ts 或从 tick.id 派生时间。
