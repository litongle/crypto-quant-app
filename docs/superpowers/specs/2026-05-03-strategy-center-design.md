# 策略中心产品设计

日期：2026-05-03

## 目标

重构策略中心，使页面信息架构、交互语义和策略生命周期保持一致。

本次设计解决的核心问题：

- 当前“快速启动 / 自定义创建 / 我的策略 / 策略实例”在语义上重叠
- 运行中的策略、已保存未运行的策略、正在编辑的策略想法混在同一个心智模型里
- 用户很难区分“我正在监控什么”“我可以复用什么”“我正在创作什么”

设计目标：

1. 让用户进入页面后先看懂当前运行状态
2. 让已保存策略有稳定、可复用的归属
3. 让新策略创建默认处于编辑态，不污染正式实例池
4. 让运行中的策略编辑与正式运行实例隔离，避免误操作

## 最终信息架构

策略中心采用“上下分区”结构，共 3 层：

1. 运行台
2. 策略仓库
3. 工作台

整体方向为：

- 结构采用“策略工坊优先”的分层逻辑
- 顶部运行台采用“中等强调”的监控表现
- 最终气质为：`策略工坊骨架 + 运行台视觉强化`

## 1. 运行台

### 作用

运行台只承载“当前正在运行的策略”。

它是监控与控制区域，不承担策略创建职责，也不承载未运行策略。

### 展示内容

- 运行中策略数量
- 当日或累计盈亏摘要
- 风险 / 告警摘要
- 2 到 4 张运行中策略卡片
- “查看全部运行中”入口

### 卡片信息

每张运行中策略卡片建议展示：

- 策略名称
- 策略模板类型
- 交易所
- 交易对
- 账户模式（实盘 / 模拟）
- 当前状态
- 最近运行表现（如当日盈亏、累计盈亏、告警）
- 最近一次启动后的运行时长

### 可执行动作

- 查看详情
- 停止
- 查看绩效
- 编辑副本

### 关键规则

- 这里只显示 `running` 状态的策略
- 不显示未启动策略
- 不显示已停止策略
- 点击“编辑”不会直接修改线上运行策略，而是复制一个工作副本到工作台

## 2. 策略仓库

### 作用

策略仓库是“已保存、可复用、当前未运行”的策略资产库。

它不是待发布区，也不是草稿区，而是用户可以长期积累、筛选、复用和再次启动的策略集合。

### 展示内容

默认采用紧凑列表，而不是卡片网格。

推荐字段：

- 策略名称
- 模板 / 分类
- 交易所
- 交易对
- 账户模式
- 最近修改时间
- 最近一次运行时间（可选）
- 操作列

### 可执行动作

- 启动
- 编辑
- 复制
- 归档 / 删除

### 关键规则

- 工作台中“保存为策略”后的结果进入策略仓库
- 运行台中的策略停止后，回到策略仓库
- 策略仓库中的策略当前不处于运行状态
- 策略仓库是资产层，不承载“临时编辑中”的对象

## 3. 工作台

### 作用

工作台是策略创作区，用于：

- 从模板出发创建策略
- 使用规则构建器自定义策略
- 调整参数
- 测试 / 回测 / 验证
- 最终保存或启动

### 展示内容

工作台默认是编辑态优先，不自动创建正式实例。

建议结构：

- 左侧：模板入口、规则构建器、参数配置、账户与标的选择
- 右侧：测试结果、策略说明、动作区

### 可执行动作

- 保存为策略
- 启动策略
- 回测 / 测试
- 丢弃草案

### 关键规则

- 进入工作台不自动落正式实例
- 用户点击“保存为策略”后，才创建正式策略资产并进入策略仓库
- 用户点击“启动策略”后，才进入运行台
- 工作台中的对象默认视为“草案 / 编辑态”，不是正式实例列表项

## 生命周期状态机

统一状态流如下：

```text
工作台草案
  -> 保存为策略
  -> 进入策略仓库

工作台草案
  -> 启动策略
  -> 进入运行台

策略仓库
  -> 启动
  -> 进入运行台

运行台
  -> 停止
  -> 回到策略仓库

运行台
  -> 编辑
  -> 复制为草案到工作台
```

## 产品语义规范

### 1. 快速启动

当前“点击模板快速创建并启动策略实例”这类文案会造成误导。

在新设计中，不再使用这种承诺“一击即启动”的语义，除非产品真的实现单击直启。

建议改为以下之一：

- 模板创建
- 快速配置
- 从模板创建

### 2. 自定义创建

“自定义创建”必须明确表示：

- 进入工作台
- 开始编辑一个新策略草案
- 不立即创建正式实例

### 3. 策略实例

“策略实例”是实现层术语，不适合作为主页面一级区块名。

面向用户的语义应替换为：

- 运行台
- 策略仓库
- 工作台

### 4. 编辑运行中策略

运行中的策略不允许直接进入“在线热更新编辑”流程。

必须通过“复制为草案到工作台”的方式进入编辑，避免把实验性改动直接打到线上运行版本。

## 页面阅读顺序

用户进入策略中心时，预期阅读路径为：

1. 先看运行台：当前有哪些策略在跑，状态是否健康
2. 再看策略仓库：有哪些已保存策略可以复用或启动
3. 最后进入工作台：开始构思和测试新策略

该路径与真实使用场景一致：

- 日常先监控正在运行的策略
- 有新想法时再进入工作台创建和测试

## 与现有实现的差异

现有页面需要重点调整的点：

1. 顶部模板分组不能再混入“全部已创建实例”
2. 运行中策略与未运行策略必须分开
3. 工作台不能默认等价于“实例已创建”
4. “草稿”如果保留，必须只属于工作台编辑态，而不是仓库态
5. 运行时长不能再使用创建时间，需要使用最近一次启动时间

## 实现边界

本设计只定义策略中心的产品结构、状态流和主要交互语义。

不在本次设计中展开的内容：

- 具体视觉样式细节
- 回测页重构
- 策略详情页独立化
- 策略仓库高级筛选器的完整字段集合

这些内容应在实现阶段按风险与优先级分拆。

## 验收标准

重构完成后，用户应能稳定回答以下问题：

1. 哪些策略正在运行？
2. 哪些策略只是保存了、但当前没跑？
3. 我现在是在编辑草案，还是在管理正式策略？
4. 我停止一个运行中的策略后，它会去哪？
5. 我编辑一个运行中的策略时，会不会直接改到线上？

若用户不能快速回答上述问题，则说明语义仍不一致。
